## What is included

Each project has six concrete scenarios practiced through eight rounds: JavaScript, React, TypeScript/JSDoc and schemas, asynchronous APIs, debugging, system design, code review, and behavioral/project explanation. That is 48 scenario/round combinations per project and 480 across the ten. There are **60 distinct scenario briefs**, not 480 claims of unrelated bugs. The round format is deliberately reused so you can compare reasoning across projects; it is not copied application source.

Separate interviewer files supply expected reasoning, pitfalls, changed-input follow-ups, and scoring guidance. Ten distinct new Node coding challenges include unfinished starters, seven supplied checks each, and separate reference answers. Thirty timed mock scripts combine cases into frontend, full-stack, and project-defense sessions. Every pack adds a study plan, project-defense worksheet, and evidence-based scorecard.

## Choose a usable path

Start with one of projects 1–4 if you need practice explaining a small JavaScript/React interaction. Use projects 5–8 to practice cache, transaction, import, and reservation boundaries. Use projects 9–10 for generated-data validation, evaluation definitions, asynchronous events, and operational evidence. This order follows the existing route and source complexity; it is not a ranking of employer demand.

Do one coding round, one React/contract round, and one mock before opening another project. The material is a practice library rather than a checklist to finish before applying. Keep reference answers closed during the first attempt. Record the source state and distinguish studied code, completed models, proposed changes, and application behavior you actually verified.

Use the [cross-project tracker](TRACKER.md), [interview foundations](FOUNDATIONS.md), and [official references](REFERENCES.md). Human mastery begins not assessed. Author test success does not fill the learner tracker or establish readiness for a particular employer.
