# Primary references for interview study

Checked 2026-09-28. These are supporting references for language/framework semantics, not a claim about any employer's interview format. Repository source and local instructions control application-specific behavior. No package versions or application code were upgraded in this content expansion.

- [React: State as a snapshot](https://react.dev/learn/state-as-a-snapshot). Review how a handler relates to the render that created it, then test your own changed-input prediction.
- [React: You might not need an Effect](https://react.dev/learn/you-might-not-need-an-effect). Use this when deciding whether work is derived display logic, a user action, or synchronization with something external.
- [TypeScript: Narrowing](https://www.typescriptlang.org/docs/handbook/2/narrowing.html). Compare a narrowed runtime branch with an unchecked assertion; they provide different evidence.
- [MDN: Using promises](https://developer.mozilla.org/en-US/docs/Web/JavaScript/Guide/Using_promises). Review promise composition and error propagation before explaining a multi-caller timeline.

The cases, fixtures, scoring, and mock scripts are original practice material tied to local projects. They are not copied interview questions, official hiring criteria, or excerpts from these pages. Refer to the current documentation when framework behavior is relevant, and verify the repository's installed version before implementing framework-specific changes.
