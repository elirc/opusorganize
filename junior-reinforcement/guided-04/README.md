## What is different in this block

The interview library asks you to respond under a timebox. This block slows the same ideas down. Every project gets six lengthy worked journals, six companion explanations, six drawing/building/speaking workshops, twenty-six transferable worked-model chapters, and a runnable notebook with three solved examples. It also adds learning pathways, a personal journal template, and a review plan.

The journals are clearly labeled fictional teaching narratives. They show an initial prediction, a plausible mistake, a corrected rule, and a reflection on what evidence is still missing. They do not invent the user's experiences or claim new production incidents. The personal template remains unfilled for the learner's own factual record.

The model chapters include concrete inputs, step tables, expected results, longer causal explanations, a tempting wrong answer, and a changed example with its resolution. Their core is intentionally shared across project packs for a self-contained reading route; the local source connections adapt the context. There are 26 transferable model topics, not 260 distinct algorithms.

## Choose a useful format today

Read a slow explanation when you need a complete causal account. Trace a table or draw ownership when the relationships are hard to hold in your head. Run a worked notebook when you want concrete values checked by code. Explain the mechanism aloud when you want to test clarity. Write a journal entry when you want to preserve the assumption that changed.

These are complementary activities, not fixed learning-style labels. You can use more than one for the same idea. The goal is to predict a changed example and explain the decisive step, not merely to finish every page.

Start with one local case and one related model. Use the earlier interview prompt after you can explain the mechanism slowly. The timebox then practices communication and prioritization rather than guessing at an unfamiliar concept. Use the [shared progress log](PROGRESS.md) to record your own evidence.

All new code is standalone teaching verification. No application behavior, dependencies, or infrastructure are changed. The [existing official-reference guide](../interview-03/REFERENCES.md) remains available for framework/language study. Human mastery stays unassessed until demonstrated.
